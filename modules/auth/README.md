# Auth service

Подтверждение личности: хранит логин и хеш пароля, проверяет пароль при входе и при его смене. После успешной проверки
в текущей сессии не участвует, дальше работает session.

### Логин и пароль

- **логин** — trim + нижний регистр, 3–32 символа: латиница, цифры и дефис, начинается с буквы
- **пароль** — от 8 символов и не длиннее 72 байт (предел bcrypt), хранится как есть, без trim
- В БД хранится только bcrypt-хеш пароля, сам пароль нигде не сохраняется и не попадает в логи

### Инварианты Credentials

| Правило                                   | Где                           | Ошибка                                   |
|-------------------------------------------|-------------------------------|------------------------------------------|
| логин соответствует формату               | NewUsername                   | ErrInvalidUsername                       |
| пароль от 8 символов и не длиннее 72 байт | NewPassword                   | ErrPasswordTooShort / ErrPasswordTooLong |
| ID пользователя не пустой, логин задан    | NewCredentials/Load           | ErrInvalidUserID / ErrInvalidUsername    |
| пароль задан                              | NewCredentials/ChangePassword | ErrInvalidPassword                       |
| хеш пароля не пустой                      | Load                          | ErrInvalidPasswordHash                   |
| пароль совпадает с хешем                  | VerifyPassword/ChangePassword | ErrWrongPassword                         |

### Поведение

При регистрации пароль сразу хешируется, в Credentials попадает только хеш. Сменить пароль можно только через
ChangePassword: сначала проверяется старый пароль, потом хешируется новый. Если старый пароль неверный, новый не прошёл
политику или хешер вернул ошибку, хеш остаётся прежним. Политика пароля действует только при задании пароля, при входе
пароль сверяется с хешем без неё, поэтому ужесточение политики не блокирует уже существующие пароли. Хеширование скрыто
за интерфейсом PasswordHasher: в проде это bcrypt, в доменных тестах — fake-хешер, поэтому тесты быстрые и не зависят
от bcrypt. Битый хеш в БД считается сбоем, а не неверным паролем. Уникальность логина обеспечивает база данных, а не
домен.
